# DocMind AI — Multi-Modal Document Intelligence RAG

DocMind AI is a multi-modal Retrieval-Augmented Generation (RAG) platform designed for querying complex PDF documents containing structured text, grid tables, and embedded images. The platform extracts content using layout-aware parsing, indexes vector embeddings alongside sparse keyword representations, and performs hybrid search powered by Reciprocal Rank Fusion (RRF) and cross-encoder re-ranking. Answers are generated by an LLM with inline citations mapping directly back to source pages and tables.

## ✨ Key Features

- **Multi-Modal Document Extraction**: Extracts paragraph text, structural grid tables, and embedded figures/diagrams from PDFs using PyMuPDF and PyTesseract OCR.
- **Hybrid Retrieval System**: Combines dense vector search (`sentence-transformers/all-MiniLM-L6-v2`) with sparse keyword search (`BM25Okapi`).
- **Reciprocal Rank Fusion (RRF)**: Merges dense vector rankings and BM25 sparse rankings using constant reciprocal weighting (`1 / (60 + rank)`).
- **Cross-Encoder Re-Ranking**: Passes top fusion candidates through a cross-encoder model (`cross-encoder/ms-marco-MiniLM-L-6-v2`) to re-score query-passage relevance.
- **Grounded Responses & Evidence**: Generates answers strictly grounded in document context with citations pointing to specific page numbers, tables, or OCR images.
- **Bring Your Own Key (BYOK) & Model Flexibility**: Supports Groq (`llama-3.1-8b-instant`) and Gemini (`gemini-1.5-flash`), with an offline fallback model (`google/flan-t5-small`).
- **User Isolation & Security**: Full JWT authentication with bcrypt password hashing and database payload filtering enforcing user-level document privacy.

## 🔄 RAG Pipeline Overview

1. **Document Upload**: PDF documents are uploaded via authenticated multi-part REST API endpoints.
2. **Multi-Modal Content Extraction**:
   - Paragraph text is parsed with layout coordinates using PyMuPDF.
   - Grid tables are detected, reconstructed, and serialized into formatted text blocks.
   - Images and charts are extracted and passed through PyTesseract OCR to generate descriptive captions.
3. **Chunking**: Content is split into semantically coherent chunks with source metadata (page numbers, table markers, image paths).
4. **Dense & Sparse Indexing**:
   - Chunks are embedded into 384-dimensional dense vectors using `all-MiniLM-L6-v2` and indexed into Qdrant.
   - Tokenized text passages are indexed into a local `BM25Okapi` sparse index.
5. **Hybrid Search Execution**: When a question is received, the system queries Qdrant (dense) and BM25 (sparse) concurrently using user-isolated payload filters.
6. **Reciprocal Rank Fusion (RRF)**: Scores from dense and sparse queries are fused into a unified candidate list.
7. **Cross-Encoder Re-Ranking**: Top fused passages are re-scored using `ms-marco-MiniLM-L-6-v2` to evaluate context relevance.
8. **Context Synthesis & Citation Generation**: Top re-ranked chunks are formatted into a prompt and submitted to the LLM. The final answer includes citation cards linking back to source pages and tables.

## 🔐 Environment Variables & BYOK

Secrets and API keys are managed via environment variables and should not be committed to source control. Refer to `.env.example` for the complete template.

| Variable Name | Description | Default / Example |
| :--- | :--- | :--- |
| `SECRET_KEY` | JWT signing secret key | `docmind-super-secret-jwt-key` |
| `DATABASE_URL` | PostgreSQL connection string | `sqlite:///./docmind.db` (Local) |
| `QDRANT_HOST` | Qdrant server host | `localhost` |
| `QDRANT_PORT` | Qdrant server port | `6333` |
| `QDRANT_URL` | Qdrant Cloud cluster endpoint | `https://your-cluster.qdrant.tech:6333` |
| `QDRANT_API_KEY` | Qdrant Cloud API key | `your-qdrant-api-key` |
| `GROQ_API_KEY` | Server-wide Groq API key (Optional) | `gsk_...` |
| `GEMINI_API_KEY` | Server-wide Gemini API key (Optional) | `AIzaSy...` |

Users can also provide their personal API keys directly in the frontend UI via **Bring Your Own Key (BYOK)** settings.

## 🛡️ Security & Software Engineering Practices

- **Authentication & Authorization**: Password hashing using direct `bcrypt` methods and stateless OAuth2 JWT tokens with configurable expiration.
- **Multi-Tenant Data Privacy**: All Qdrant vector points and SQL queries filter by `user_id` to prevent cross-account document access.
- **Input Validation**: All incoming API payloads are validated using Pydantic v2 schemas.
- **Containerization**: Standardized Docker environment ensuring consistency between local execution and cloud deployments.
- **System Health Monitoring**: Dedicated `/health` endpoint exposing real-time service status.
